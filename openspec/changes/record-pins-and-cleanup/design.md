# Design

## Context

동기는 proposal.md를 따른다. 현재 Handover는 고정 필드가 없고 schemaVersion 1의 records를 하나의 Storage 키에 저장한다. storage.ts는 읽기 오류·손상·미지원 형식에서 쓰기를 막고 persistRecords 성공 후에만 상태를 돌려준다. saveHandover는 draft에서 새 객체를 만들므로 고정 상태를 명시적으로 보존해야 한다. App은 mutationLock으로 쓰기를 직렬화하고 graniteEvent backEvent를 화면 상태별로 처리한다. 목록과 홈 최근 3건은 sortHandovers를 공유한다.

정식 명세는 아직 없고 handover-mvp 변경의 REC-02가 날짜순 전체 목록을 규정한다. 이 문서는 이를 무시하거나 해당 MVP를 완료·archive 처리하지 않는다.

## Goals / Non-Goals

**Goals:** 기존 기록을 보존하며 고정과 일괄 정리를 같은 저장 경계에서 처리하고, 홈 최근 기록과 목록 정렬을 분리한다.

**Non-Goals:** 서버·새 저장 계층·상태 관리 라이브러리, 사용자 템플릿, 고정 순서 수동 이동, 복구함과 전체 초기화.

## Decisions

### 1. 고정은 저장된 기록의 선택적 boolean 메타데이터

Handover에 isPinned?: boolean을 추가하고 누락은 false로 취급한다. 있으면 반드시 boolean으로 검증한다. 키와 schemaVersion 1은 유지한다. 별도 pinnedIds 저장소는 두 키 쓰기의 부분 실패와 삭제 후 유령 참조가 생겨 채택하지 않는다. v2로 옮기면 현재 앱이 전체 저장소를 미지원으로 판단하므로 이번에는 선택 필드 확장을 사용한다.

신규 기록은 미고정, 수정 저장은 기존 고정값을 보존한다. 고정 전환은 본문·createdAt·updatedAt을 바꾸지 않는다. 기존 객체를 복사해 필드를 갱신하고 한 envelope를 저장한다. 이전 앱도 확장 필드를 거부하지 않지만 수정 저장 시 고정값을 유실할 수 있어 구버전 동시 사용·롤백은 고정 유지 보장 대상이 아니다.

### 2. 목록 전용 정렬

기존 sortHandovers와 getRecentHandovers의 날짜순 의미를 유지하고 전체 목록용 정렬을 분리한다. 고정 그룹을 먼저 배치하며 각 그룹 안은 업무 날짜 내림차순, 수정 시각 내림차순이다. 동률 순서는 기존과 같이 보장하지 않는다. App에서 공용 records 전체를 고정순으로 바꾸어 홈에 전파하는 방식은 피한다.

### 3. 설정의 명확한 선택 삭제

정상 로드된 모든 일반 화면의 플랫폼 내비게이션에 설정 톱니바퀴 액세서리 버튼, settings 화면에는 전체·보존·삭제 예정 수와 ‘고정하지 않은 기록 삭제’를 둔다. 확인창에 삭제 수·보존 수와 복구 불가를 알리고 취소를 기본 선택으로 둔다. 대상이 0이면 실행을 막고 안내한다. 고정 기록도 개별 삭제는 기존 확인 절차로 허용한다.

단일 mutationLock을 저장·개별 삭제·고정·일괄 삭제가 공유한다. 확인창이 열린 동안 데이터 변경 조작을 막고 실제 실행 시에도 최신 ready 상태로 대상을 계산한다. 단 한 번의 envelope 쓰기 성공 후 화면 상태를 교체한다. 실패 시 화면 기록·카운트·원본을 유지한다. removeItem·Storage 전체 초기화 API는 쓰지 않는다. 전부 미고정이면 빈 records를 저장한다.

### 4. 화면과 이동

홈·목록 카드는 열기 버튼과 우측 상단 고정 버튼을 형제 요소로 두어 button 중첩을 피한다. 상세의 고정 버튼도 제목 우측 상단에 둔다. 고정 버튼은 SVG 아이콘과 접근 가능한 ‘고정’/‘고정 해제’ 이름 및 상태를 제공하고 44px 이상이다. 상세에도 동일 조작을 둔다. 홈 최근 목록에도 동일한 고정 버튼을 카드 우측 상단에 제공하고 최근 기록의 정렬은 날짜순을 유지한다.

설정은 모든 일반 화면에서 진입한다. 작성 입력·저장 스냅샷은 보존하고 플랫폼 상단·시스템 뒤로가기는 설정→진입 직전 화면으로 연결하며 확인창이 열려 있으면 삭제를 실행하지 않고 닫는다. 저장 중 중복 뒤로가기·삭제를 막는다. 자체 상단 내비게이션이나 광고를 설정에 추가하지 않는다. 화면 구현은 ait:design과 기존 토큰을 따른다.

## Risks / Trade-offs

- [삭제 오인] → ‘초기화’ 대신 삭제 대상과 보존 수가 명확한 문구·확인창을 사용한다.
- [손상 데이터에서 고정값 판단 불가] → 고정·정리도 차단하고 원문 보호·재시도 정책을 유지한다.
- [구버전의 고정 필드 유실] → 테스트 링크와 운영 버전을 구분하고 롤백 시 영향 안내. 데이터 삭제를 되돌리는 기능은 없다.
- [광고 조건 변화] → 목록 크기 변화에도 기존 배너 오버플로 판정과 정리가 작동하는지 확인한다.
- [활성 명세 충돌] → 구현 첫 작업에서 REC-02를 고정 우선·홈 날짜순으로 조정한다. MVP archive 시 본 변경을 누락하거나 중복 덮어쓰지 않도록 순서를 확인한다.

## Migration Plan

기존 v1·신규 선택 필드·잘못된 타입 fixture를 먼저 검증한다. 기동 시 자동 쓰기·일괄 변환은 하지 않는다. 사용자 조작 시에만 확장 필드를 저장한다. 수정본을 콘솔 테스트 번들로 배포하고 S26U에서 기존 기록 유지→고정→재실행→선택 정리 순으로 확인한다. 삭제 검증은 별도로 만든 테스트 기록으로 한다. 실기기 검증·검수·출시는 별개이며 새 사용자 요청 없이 구현하거나 공개하지 않는다.

### UI 수정 반영 (2026-10-23)

플랫폼에 앱 이름·아이콘이 있으므로 화면 내부의 작은 인계한장 이름표를 제거한다. 홈 설정 버튼은 partner.addAccessoryButton과 tdsEvent의 navigationAccessoryEvent로 연결하고, 모든 일반 화면에서 노출한다. 설정의 첫 섹션은 기록 정리이며 권한 안내는 아래에 둔다. 아이콘은 공식 자산 icon-setting-mono를 사용한다. 설정 화면과 기록 정리 동작은 유지한다.
