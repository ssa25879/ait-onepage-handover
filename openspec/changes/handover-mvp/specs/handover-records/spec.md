# 기록 관리

## Purpose

기기 로컬에서 인수인계 기록을 생성하고 다시 찾아 수정하거나 삭제할 수 있게 한다. 저장·읽기 실패와 손상된 데이터가 기존 기록의 조용한 소실로 이어지지 않도록 관찰 가능한 동작을 정의한다.

## ADDED Requirements

### Requirement: REC-01 영속 저장과 수정 (F-03 F-04 F-08)
시스템 SHALL 신규 기록에 고유 ID와 작성·수정 시각을 부여하고 동일 날짜의 복수 기록을 허용한다. 수정은 ID·최초 작성 시각을 유지하고 수정 시각만 갱신한다. 영속 저장 성공 후에만 성공을 안내하고 화면의 확정 상태에 반영한다.

#### Scenario: T-04 T-05 생성과 재실행
- **WHEN** 유효 내용을 저장한 뒤 앱을 종료하고 다시 실행한다
- **THEN** 생성한 기록을 동일 내용으로 조회할 수 있다

#### Scenario: T-06 기존 기록 수정
- **WHEN** 기존 기록을 수정하고 저장한다
- **THEN** ID·createdAt은 유지되고 내용·updatedAt이 갱신되며 복제 기록이 생기지 않는다

#### Scenario: T-11 저장 거절
- **WHEN** 저장소 쓰기가 실패한다
- **THEN** 성공 안내 없이 재시도를 안내하고 입력·원본 기록을 보존한다

#### Scenario: 중복 조작
- **WHEN** 저장 또는 삭제가 진행 중인데 같은 변경 동작을 연속 요청한다
- **THEN** 중복 기록이나 다른 기록의 유실 없이 한 번의 확정 결과를 반영한다

### Requirement: REC-02 정렬과 탐색 (F-07)
시스템 SHALL 업무 날짜 내림차순, 같은 날짜는 수정 시각 내림차순으로 전체 기록을 탐색하게 한다. 홈은 같은 순서로 최근 최대 3건을 표시하고 목록·상세·수정으로 연결한다. 동일한 날짜·수정 시각의 동률 순서는 보장하지 않는다.

#### Scenario: 날짜와 수정 시각 정렬
- **WHEN** 업무 날짜와 수정 시각이 다른 기록들이 있다
- **THEN** 업무 날짜를 우선하고 같은 날짜만 수정 시각으로 정렬하며 오래된 기록도 목록에서 접근 가능하다

#### Scenario: T-14 빈 목록
- **WHEN** 정상 조회 결과 기록이 0건이다
- **THEN** 홈과 목록에 빈 상태 및 새 작성 진입을 제공한다

#### Scenario: 존재하지 않는 기록
- **WHEN** 상세 또는 수정 대상 ID가 현재 기록에 없다
- **THEN** 찾을 수 없음을 안내하고 목록으로 이동할 수 있게 하며 새 기록으로 자동 저장하지 않는다

### Requirement: REC-03 확인 후 삭제 (F-05 F-08)
시스템 SHALL 대상 기록을 명확하게 표시하여 삭제를 확인받고, 성공 시 선택한 기록만 제거한다. 삭제 실패 시 원본을 유지하고 실패를 안내한다.

#### Scenario: T-07 삭제 취소
- **WHEN** 삭제 확인에서 취소한다
- **THEN** 저장소를 변경하지 않고 기존 기록을 유지한다

#### Scenario: T-08 삭제 확인
- **WHEN** 특정 기록의 삭제를 확인하고 저장소 변경이 성공한다
- **THEN** 해당 기록만 제거하고 갱신된 목록으로 이동한다

#### Scenario: 삭제 실패
- **WHEN** 확인 후 저장소 변경이 실패한다
- **THEN** 원본·다른 기록을 유지하고 성공으로 안내하지 않는다

### Requirement: REC-04 읽기 실패와 손상 데이터 보호
시스템 SHALL 데이터 없음과 읽기 실패·손상·미지원 형식을 구별한다. 실패·손상 상태에서는 기존 저장값을 자동 덮어쓰거나 초기화하지 않으며 저장·수정·삭제를 차단하고 재시도 안내를 제공한다.

#### Scenario: 최초 사용
- **WHEN** 저장소 조회가 성공하고 저장된 키가 없다
- **THEN** 정상적인 빈 기록 상태로 시작한다

#### Scenario: 손상된 JSON 또는 미지원 버전
- **WHEN** JSON 파싱·필드 검증이 실패하거나 schemaVersion이 지원되지 않는다
- **THEN** 오류를 안내하고 원본 저장 문자열을 보존하며 빈 배열로 덮어쓰지 않는다

#### Scenario: 읽기 재시도
- **WHEN** 읽기 오류 후 사용자가 재시도하여 정상 데이터를 받는다
- **THEN** 정상 기록을 표시하고 변경 동작을 다시 허용한다
