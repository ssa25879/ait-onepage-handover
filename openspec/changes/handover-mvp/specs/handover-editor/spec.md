# 작성 및 편집

## Purpose

세 업무 유형에 공통된 입력 흐름을 제공하여 인수인계 내용을 빠짐없이 작성하게 하고, 검증 오류와 화면 이탈 때문에 사용자가 입력한 내용이 유실되지 않도록 한다.

## ADDED Requirements

### Requirement: ED-01 템플릿과 공통 입력 (F-01 F-02)
시스템 SHALL cafe·retail·general 템플릿을 제공하고 동일한 날짜·완료 업무·진행 중 업무·전달사항 필드를 사용한다. 템플릿별 안내와 예시만 달라야 한다. 날짜 기본값은 기기 현지 오늘이며 변경 가능해야 한다.

#### Scenario: T-01 유형 선택
- **WHEN** 사용자가 템플릿 3종을 각각 선택한다
- **THEN** 선택한 유형과 업무별 안내가 표시되고 공통 필드가 제공된다

#### Scenario: T-02 여러 줄과 날짜
- **WHEN** 날짜를 변경하고 각 본문에 여러 줄을 입력한다
- **THEN** 입력값과 줄바꿈이 유지되며 다른 필드 편집으로 사라지지 않는다

### Requirement: ED-02 저장 전 검증 (F-02 F-08)
시스템 SHALL 유효한 YYYY-MM-DD 날짜와 공백 아닌 본문 한 항목 이상을 저장 조건으로 검사한다. 모든 본문이 공백이면 저장을 거절하고 입력값과 수정 대상을 보존한다.

#### Scenario: T-03 공백 또는 잘못된 날짜
- **WHEN** 본문이 모두 빈 문자열·공백·줄바꿈이거나 날짜가 유효한 달력 날짜가 아니다
- **THEN** 원인을 안내하고 저장을 호출하지 않는다

#### Scenario: 한 항목만 작성
- **WHEN** 유효한 날짜와 한 본문에만 실제 내용이 있다
- **THEN** 빈 나머지 본문 때문에 저장을 거절하지 않는다

### Requirement: ED-03 미저장 변경 이탈 확인 (F-10)
시스템 SHALL 새 작성 초기값 또는 마지막 저장 성공 상태와 다른 입력이 있을 때 앱 내부 이동·플랫폼 뒤로가기·Android 시스템 뒤로가기에 이탈 확인을 제공한다. 복사는 미저장 상태를 해제하지 않는다. 강제 종료 시 복구는 보장하지 않는다.

#### Scenario: T-13 이탈 취소와 확인
- **WHEN** 수정 후 뒤로가고 이탈을 취소한다
- **THEN** 현재 화면과 모든 입력이 보존된다

#### Scenario: 명시적 이탈
- **WHEN** 미저장 변경 확인에서 나가기를 선택한다
- **THEN** 이전 화면으로 이동하고 미저장 변경은 저장하지 않는다

#### Scenario: 변경 복원 또는 저장 성공
- **WHEN** 입력을 기준 상태와 같게 되돌리거나 저장이 성공한다
- **THEN** 추가 변경 없이 뒤로갈 때 불필요한 확인을 띄우지 않는다
