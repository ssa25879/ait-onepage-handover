# 미니앱 품질과 검증

## Purpose

인수인계 작성과 기록 탐색을 작은 모바일 화면과 실제 토스 앱에서도 수행할 수 있게 한다. 로컬 데이터의 보존 한계와 개인정보 처리 범위를 안내하고 자동화·실기기·출시 결과를 구분하여 보고한다.

## ADDED Requirements

### Requirement: Q-01 모바일 입력과 플랫폼 이동
시스템 SHALL 라이트 모드와 플랫폼 내비게이션을 사용하고 자체 상단 내비게이션을 중복 표시하지 않는다. 본문 글자 15px 이상·모든 글자 11px 초과·터치 영역 44px 이상·하단 CTA safe area 34px을 보장하고 한글 어절 줄바꿈을 유지한다. 키보드가 열려도 입력과 주요 버튼에 접근 가능해야 한다.

#### Scenario: 작은 화면과 키보드
- **WHEN** Android 토스 앱의 작은 화면에서 긴 여러 줄 본문을 입력하고 키보드를 연다
- **THEN** 입력·버튼이 겹치거나 잘리지 않고 스크롤로 저장·복사에 접근할 수 있다

#### Scenario: 홈과 하위 화면 뒤로가기
- **WHEN** Android 시스템 또는 플랫폼 뒤로가기를 실행한다
- **THEN** 하위 화면은 이전 화면으로, 홈은 앱 종료로 동작하며 미저장 편집은 ED-03 확인을 거친다

### Requirement: Q-02 로컬 보존과 정보 처리 안내
시스템 SHALL 로컬 저장·기기 변경 시 미복원·앱 데이터 초기화 시 유실 가능성·별도 서버 백업 없음을 안내한다. 민감한 고객·비밀번호·사업장 정보 입력을 피하도록 안내하고, 본문을 자체 서버·광고 이벤트·디버그 로그에 전송하거나 기록하지 않는다. 광고 SDK의 네트워크 사용 가능성은 구별한다.

#### Scenario: 보존 한계와 복사 안내
- **WHEN** 사용자가 홈 또는 작성 화면에서 보존·정보 안내를 확인한다
- **THEN** 중요 내용의 별도 복사 보관과 클립보드 이후 외부 앱 전달에 주의할 수 있는 설명을 읽을 수 있다

#### Scenario: 오류와 광고 이벤트
- **WHEN** 저장·복사·광고 처리 중 오류 또는 이벤트가 발생한다
- **THEN** 진단·광고 데이터에 본문이 포함되지 않는다

### Requirement: Q-03 검증과 완료 상태의 구분
프로젝트 SHALL 타입·lint·빌드 및 로직 테스트 결과와 Android 실기기 결과를 분리한다. Android 재실행 저장·외부 앱 붙여넣기·뒤로가기·키보드·광고를 실제 확인하기 전 실기기 통과로 기록하지 않는다. iOS와 미구현 선택 기능은 미검증·구현 제외로 기록하고 개발 완료와 심사 승인·공개를 구분한다.

#### Scenario: 정적 검사만 성공
- **WHEN** 타입·빌드·로직 테스트는 성공했지만 Android SDK 동작은 실행하지 않았다
- **THEN** Android 동작을 미검증으로 남기고 MVP 전체 완료로 선언하지 않는다

#### Scenario: Android 검증 보고
- **WHEN** Android 실기기 결과를 기록한다
- **THEN** 기기·OS·토스 앱·SDK 버전, 일시·시나리오·기대/실제 결과와 증거를 포함하며 iOS 미검증을 유지한다

#### Scenario: UX 목표 측정
- **WHEN** Android에서 첫 작성부터 저장·복사까지 실제 사용 흐름을 측정한다
- **THEN** 템플릿 선택 시점부터 복사 성공까지 소요 시간과 입력 분량·조건을 기록하고 2분 목표 달성 여부를 판정한다
