# 인계한장 MVP 구현 작업

유일한 구현 체크리스트다. 모든 작업은 미착수이며 문서 생성은 아래 작업의 완료가 아니다. [설계](design.md)와 [기획서](source-plan.md)를 함께 읽는다. 구현은 명세 검토 후 별도 요청 시 시작한다.

## 1. 기반과 작성 (Day 1)

- [x] 1.1 현재 SDK 3.8.1의 Storage·Clipboard·TossAds 타입과 플랫폼 뒤로가기 등록/해제 API, 앱 설정을 확인한다. 검증: 설치 타입·공식 API와 호출 경로를 대조하고 콘솔 appName 일치 확인 전까지 외부 상태를 미확인으로 기록한다. 요구사항: Q-01, Q-03.
- [x] 1.2 모델·템플릿·날짜/본문 검증을 구현하고 적절한 로직 테스트 실행 수단을 구성한다. 검증: T-01~T-03, 한 항목 유효·잘못된 날짜·현지 날짜 경계 테스트를 먼저 실패 재현한 뒤 통과시킨다. 요구사항: ED-01~ED-02.
- [x] 1.3 ait:design으로 홈·템플릿·작성 화면을 기존 토큰에 맞춰 구현한다. 검증: 3종 안내·여러 줄 입력·날짜 변경을 브라우저에서 확인하고 본문 15px/터치 44px/CTA safe area/한글 줄바꿈을 점검한다. 요구사항: ED-01, Q-01.

## 2. 로컬 기록 (Day 2)

- [x] 2.1 envelope 읽기·형식 검증과 로드 상태를 구현한다. 검증: 키 없음·정상·읽기 거절·JSON 손상·미지원 버전·필드 오류·중복 ID에서 원본을 덮어쓰지 않고 쓰기를 차단하는 테스트를 통과시킨다. 요구사항: REC-04.
- [x] 2.2 신규 저장·수정·삭제를 성공 후 확정 방식으로 구현한다. 검증: T-04/T-06~T-08/T-11 및 삭제 실패·연속 저장/삭제에서 ID·createdAt 유지, updatedAt 갱신, 타 기록 보존, 실패 시 입력 유지 테스트를 통과시킨다. 요구사항: REC-01, REC-03.
- [x] 2.3 홈 최근 최대 3건·전체 목록·상세·수정·삭제 흐름을 연결한다. 검증: 날짜/수정 시각 정렬, 같은 날짜 여러 기록, 0건, 없는 ID, 목록의 마지막 기록 접근을 확인한다. 요구사항: REC-02, T-14.
- [x] 2.4 보존 한계·민감 정보·복사 보관 안내를 표시하고 본문 로그/광고 전송을 차단한다. 검증: 안내 문구와 실제 저장·전송 경로를 대조하고 오류 로그·이벤트 데이터에 본문이 없는지 점검한다. 요구사항: Q-02.

## 3. 복사 (Day 2)

- [x] 3.1 정확한 복사 문자열 생성과 입력 검증을 구현한다. 검증: T-09/T-10, 모든 템플릿 이름, 여러 줄·공백·빈 섹션·사용자 기호·끝 줄바꿈 규칙의 문자열 테스트를 통과시킨다. 요구사항: COPY-01~COPY-02.
- [x] 3.2 편집·상세의 Clipboard 호출과 결과 안내를 연결한다. 검증: T-12 및 미지원·미저장 복사에서 쓰기 완료 전 성공을 알리지 않고 원본·dirty 상태가 유지되며 빈 문서 복사는 호출되지 않는 테스트를 통과시킨다. 요구사항: COPY-02.

## 4. 이탈과 모바일 품질 (Day 3)

- [x] 4.1 초기/최근 저장 스냅샷 기준 dirty와 공통 이탈 확인을 연결한다. 검증: T-13의 취소/확인, 값 원복, 저장 성공/실패, 복사 뒤 이탈, 앱 내부 이동·플랫폼 뒤로가기·Android 백버튼을 확인한다. 자동화는 상태 전이, 실제 백버튼은 6.1에서 검증한다. 요구사항: ED-03, Q-01.
- [x] 4.2 전체 5개 화면의 로딩·빈 상태·오류·키보드·라이트 모드를 정리한다. 검증: 작은 화면/긴 본문 브라우저 흐름, 겹침·잘림·버튼 접근·글자/터치 크기·중복 상단 네비 없음 확인. 화면 수정은 ait:design을 사용한다. 요구사항: Q-01, REC-02~REC-04.

## 5. 조건부 배너 (Day 3)

- [x] 5.1 테스트 ID와 운영 ID를 UI 밖 설정으로 분리하고 앱 수준 초기화·지원 확인·화면 수준 attach/destroy를 구현한다. 검증: AD-02~AD-04/AD-06/AD-08의 mock 실패·늦은 콜백·반복 mount/cleanup 및 StrictMode에서 중복 초기화/배너가 없음을 확인한다. 요구사항: AD-REQ-02~AD-REQ-03.
- [x] 5.2 광고 없는 기록 콘텐츠로 스크롤 조건을 측정하고 인라인 배너를 연결한다. 검증: AD-01/AD-05/AD-07, 빈 목록·짧은 목록·긴 목록·높이 변경·삭제 후 비스크롤 조건·실패 슬롯 제거를 확인한다. 광고가 스스로 노출 조건을 만들지 않아야 한다. 요구사항: AD-REQ-01~AD-REQ-02.

## 6. 통합 검증과 출시 인계 (Day 3~4)

- [ ] 6.1 Android 실제 토스 앱 테스트 환경에서 T-01~T-14, AD-01~AD-08 및 REC-04 손상 보호를 검증한다. 검증: 앱 종료/재실행 저장 T-05, 외부 앱 붙여넣기 T-09, 상단/시스템 뒤로가기, 키보드, 네트워크 불안정·광고 실패·연속 화면 왕복, 누적/긴 기록을 포함한다. 샌드박스 광고 통과로 대체하지 않고 콘솔 QR 테스트를 사용한다. 기기·OS·토스 앱·SDK 버전·일시·기대/실제·증거를 남긴다. 요구사항: Q-03 및 전체 capability.
- [ ] 6.2 첫 사용 흐름의 UX 목표와 통합 빌드를 확인한다. 검증: 입력 예시 분량·기기 조건과 함께 템플릿 선택→복사 성공 시간을 재서 2분 목표 달성 여부를 기록한다. `npm run lint`, `npx tsc -b`, `npm run build`와 1.2에서 정한 로직 테스트를 실행하고 결과를 구분한다. 기존 build 스크립트는 tsc·Vite·ait build를 포함하며 불필요한 재실행은 하지 않는다. 요구사항: Q-03.
- [ ] 6.3 출시 인계 자료에 구현·미구현·미검증·외부 조건을 정리한다. 검증: P0 전부와 F-10 완료, P1 광고 결과 및 운영 그룹/실제 노출 확인, 최신 출시 가이드·광고/정산 조건·앱 설명·로고 준비 상태를 대조한다. iOS 미검증, F-11/F-12 구현 제외, 심사·공개 별도를 명시하고 확인되지 않은 외부 조건은 완료 처리하지 않는다. 요구사항: AD-REQ-03, Q-02~Q-03.

## Workflow follow-up

- P2 조사로 한국어 로컬 OCR 모델 크기·성능·라이선스·WebView 호환성과 카메라 API 지원을 확인할 수 있으나, 구현 도입은 별도 변경안에서 결정한다.
- 명세 검토 후 새 구현 요청을 받으면 openspec-apply-change와 codex-skills:feature-execution에 변경 ID handover-mvp 및 이 tasks.md를 전달한다. 추가 체크리스트는 만들지 않는다.
- 검증이 통과하고 사용자 승인 요건이 충족된 뒤에만 별도 Archive를 진행한다. 문서 검증만으로 변경을 완료·동기화·Archive하지 않는다.
- 커밋·푸시·테스트 번들 업로드·심사 제출·공개는 각각 승인된 범위에서 진행한다.
