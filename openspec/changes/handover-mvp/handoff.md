# 인계한장 MVP 작업 인계

**기준일:** 2026-10-23 (KST)\
**상태:** 클립보드 권한 수정과 새 `.ait` 빌드·콘솔 테스트 배포 완료. 2026-10-23 사용자가 S26U에서 수정본의 복사 기능과 저장 후 앱 재실행 시 기록 유지를 확인했다고 보고했다. 전체 Android 검증, 최초 앱 정보·번들 검토 제출, 공개 준비는 미완료.

## 완료한 구현과 로컬 검증

- OpenSpec 작업 1.1~5.2를 구현하고 체크리스트에 완료 표시했다.
- 홈·템플릿 3종·작성·기록 목록·상세·수정·삭제 화면, 로컬 Storage, 날짜/본문 검증, 복사 형식, dirty 이탈 확인, 조건부 배너를 연결했다.
- `npm test`: 35개 통과. Storage·Clipboard·광고 SDK 경계는 주입한 mock으로 검증했다.
- 첫 Android 토스 앱 확인에서 복사 버튼의 권한 창에서 `허용` 또는 `한 번만 허용`을 눌러도 복사되지 않는 현상을 사용자가 보고했다. 설정의 `permissions`가 비어 있었고 SDK 문서상 `Clipboard.setText`에는 `clipboard` 쓰기 권한 선언이 필요해 이를 추가했다.
- 권한 수정 뒤 `npm run build`가 통과했다. 새 번들 `20261023-2` (`01a16670-9f71-7d9d-9ce9-9f29abef93af`)은 콘솔 컴파일 `CREATED`까지 확인했고 테스트 푸시를 보냈다. 사용자가 S26U에서 수정본 복사 기능 확인 완료를 보고했다. 사용자 보고 환경은 One UI 9.0(최신), 토스 앱 최신 버전이다. Android 버전·OS 빌드 번호·토스 앱의 정확한 버전 번호는 미기록이다. 이 설정 수정 후 별도 단위 테스트는 실행하지 않았다.
- 테스트용 워크스페이스는 `YWS_WorkSpace`(ID `96603`), 앱 초안은 `miniAppId=90479`, appName은 `onepage-handover`다. 기획서의 표시 이름은 `인계한장`이다. SDK 요구사항으로 `titleEn`은 `One Page Handover`로 입력했다.
- `openspec validate handover-mvp --strict`: 유효.
- Chrome 헤드리스에서 홈→템플릿→작성 및 저장·수정·삭제 흐름을 확인했다. 390px 너비에서 템플릿 안내와 날짜 기본값, 320×470px 뷰포트의 긴 본문 입력·버튼 접근을 확인했다. 실제 토스 앱 WebView 검증으로 간주하지 않는다.

## 아직 확인해야 하는 외부·실기기 조건

- 2026-10-23 사용자 보고 기준 S26U에서 복사 기능과 T-05 저장 후 앱 재실행 시 기록 유지를 확인했다. 환경은 One UI 9.0(사용자 보고 기준 최신), 토스 앱 최신 버전이며 Android 버전·OS 빌드 번호·토스 앱의 정확한 버전 번호는 미기록이다. 나머지 T-01~T-14, AD-01~AD-08, 손상 데이터 보호 검증은 남아 있다.
- 최초 `miniapp_create` 응답은 4103으로 앱 정보 검토 제출을 거절했다. 응답에 따르면 앱은 생성됐지만 appName 외 앱 정보는 저장되지 않았으며, 최초 등록은 앱 정보와 번들을 함께 내야 한다. 세션에 `initial_review_submit` MCP 도구가 없으므로 실제 최초 제출은 콘솔 웹에서 처리해야 한다. 기존 앱 ID `90479`를 재사용하고 앱을 다시 만들지 않는다.
- 개발 환경은 테스트 그룹 ID를 사용한다. 운영용 `VITE_TOSS_AD_GROUP_ID`는 이 작업공간 환경과 `.env*` 파일에 설정되어 있지 않아 운영 빌드에서는 광고가 숨겨진다. 실제 그룹 생성·노출 결과도 확인하지 않았다.
- 공식 광고 안내의 사업자 정보·정산 정보·광고 그룹 설정은 콘솔에서 확인해야 한다. 정산 조건은 변경될 수 있으므로 실제 운영 전 최신 안내와 파트너 계정 상태를 다시 대조한다.
- 등록용 600×600 PNG `public/onepage-handover-icon.png`를 만들었고 콘솔 임시 업로드를 시도했으나 앱 정보는 저장되지 않았다. 최초 제출 전에 로고와 앱 설명·카테고리·키워드 저장 여부를 콘솔에서 확인하고 필요하면 다시 올린다. 등록 스크린샷은 준비되지 않았다.
- 첫 사용의 템플릿 선택→복사 성공 2분 목표는 실제 Android 사용자 흐름에서 측정하지 않았다. iOS는 미검증이며 카메라(F-11)·OCR(F-12)는 이번 MVP 구현에서 제외했다. 검토 승인·출시는 진행하지 않았다.

- 2026-10-23 사용자 보고 기준 S26U에서 T-13을 확인했다. 상단·Android 시스템 뒤로가기의 이탈 안내, 취소 시 입력 유지, 나가기 시 미저장 변경 폐기와 기존 저장 내용 유지를 확인했다.

- 2026-10-23 사용자 보고 기준 S26U에서 키보드를 연 상태의 긴 본문 입력과 스크롤을 통한 저장·복사 버튼 접근 및 실행이 가능함을 확인했다.

- 2026-10-23 사용자 보고 기준 S26U에서 카카오톡에 붙여넣어 T-09 복사 형식을 확인했다. 완료·진행·전달의 세 섹션, 본문 줄 순서와 `- ` 표시가 유지되고 누락·중복 없이 정상적으로 복사됨을 확인했다.

- 2026-10-23 사용자 보고 기준 S26U에서 미저장 복사와 저장의 독립성(COPY-02)을 확인했다. 저장하지 않은 수정 내용이 카카오톡에 붙여넣어지고, 복사 후에도 뒤로가기 시 미저장 이탈 안내가 표시되며, 나가기 후 기록을 다시 열면 원래 저장 내용이 유지된다.

- 2026-10-23 사용자 보고 기준 S26U에서 본문 세 칸이 모두 비어 있을 때 저장·복사 시 입력 안내가 표시되고, 빈 기록이 저장되지 않으며 기존 클립보드 내용이 유지됨을 확인했다.

- 2026-10-23 사용자 보고 기준 S26U에서 본문 한 칸만 입력해 저장할 수 있고, 카카오톡 복사 결과에서 빈 섹션이 생략됨을 확인했다.
- 중복 뒤로가기 수정: PageHeader의 자체 이전 화면 버튼을 제거했다. 수정본 `20261023-3` (`01a16703-92e7-7a02-baf1-e07acfaa04d8`)의 콘솔 컴파일 CREATED와 테스트 푸시 발송을 확인했고, 2026-10-23 사용자가 S26U에서 중복 해소와 미저장 이탈 안내의 정상 동작을 확인했다고 보고했다. 수정 후 타입·lint·기존 테스트 35개·빌드·diff 검사가 통과했다.

## 다음 작업

1. 토스 앱의 정확한 버전 번호를 보완한다.
2. Android 토스 앱에서 광고 실패·복귀, 누적 기록과 손상 데이터 보호를 확인하고 6.1에 기기·OS·토스 앱 버전 및 결과를 적는다.
3. 앱 정보와 번들을 콘솔 웹에서 함께 최초 검토 제출한다. `miniAppId=90479`를 재사용하고, 앱 이름·설명·로고·카테고리·키워드가 올바르게 저장됐는지 제출 전에 확인한다.
4. 파트너 계정의 사업자/정산 정보와 운영 광고 그룹을 확인하고 `VITE_TOSS_AD_GROUP_ID`를 설정해 운영 광고 노출을 검증한다.
5. 최신 비게임 출시 가이드와 검토 절차를 다시 대조한 뒤 6.1~6.3 체크리스트를 갱신한다.

## 후속 기능 후보 (미구현)

2026-10-23 사용자 요청으로 추가했다. 현재 MVP 6.1~6.3의 완료 조건에 포함하지 않으며, 후속 변경에서 요구사항을 확정한 뒤 구현한다.

- **앱 내 설정·기록 초기화:** 설정에서 저장된 기록을 초기화하는 기능. 초기화 대상(전체 기록·핀 상태 등), 삭제 범위 안내와 명시적 확인·취소, 삭제 실패 시 기존 기록 보존을 설계한다. 실제 사용자 기록 삭제는 이번 문서 갱신에 포함하지 않는다.
- **자주 쓰는 기록 핀 고정:** 자주 참고하는 기록을 고정·해제하는 기능. 구현 전 고정 기록의 목록 내 우선 표시 방식과 홈 표시 여부, 개수 제한을 결정한다. 재실행 후 고정 상태 유지, 기존 기록 데이터 호환, 수정·삭제 시 고정 상태 처리를 검증 항목으로 둔다.
