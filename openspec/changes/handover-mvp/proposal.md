# 인계한장 MVP 변경 제안

## Why

교대근무 인수인계의 누락과 형식 불일치를 줄이고, 템플릿 선택부터 저장·복사까지 짧은 흐름으로 제공한다. 기획서 v1.1을 실행 가능한 요구사항과 검증 기준으로 바꾼다.

## What Changes

- P0: 템플릿 3종, 날짜·본문 입력, 로컬 저장·조회·수정·삭제, 텍스트 복사, 성공·실패 안내.
- P1: 미저장 변경 이탈 확인과 스크롤 가능한 기록 목록 하단 배너 1개. 이탈 방지는 기획서 최종 완료 기준에 따라 MVP 출시에 필수다.
- Android 토스 앱에서 실제 저장·재실행·복사·뒤로가기·광고·키보드를 검증한다. iOS는 미검증으로 남긴다.
- P2 카메라·OCR은 이번 구현 명세에서 제외한다. Day 4 여유가 있을 때 별도 조사 결과만 남기며 도입은 후속 변경으로 결정한다.
- 자체 로그인·서버·동기화·결제·AI 요약·검색·복제·자동 임시 저장은 제외한다.

## Capabilities

### New Capabilities

- `handover-editor`: 업무 템플릿, 입력 검증, 편집 상태와 이탈 방지.
- `handover-records`: 기록의 영속 저장, 정렬·탐색·수정·삭제와 손상 데이터 보호.
- `handover-copy`: 저장 여부와 독립적인 본문 텍스트 생성·클립보드 복사.
- `history-banner`: 기록 목록 조건부 광고와 실패 격리·정리.
- `miniapp-quality`: 모바일 UI, 개인정보 안내와 Android 검증·출시 경계.

### Modified Capabilities

없음. 현재 등록된 OpenSpec capability는 없다.

## Impact

- 현재 브랜치 `main`, 기준 HEAD `9374d3c`. React 스타터만 있고 업무 화면·저장·복사·광고는 미구현이다.
- 설치 선언: React + TypeScript + Vite, `@apps-in-toss/web-framework` 3.8.1. TDS 패키지는 없다. 설치·버전 변경은 이번 작업에 포함하지 않는다.
- 구현 시 `src/App.tsx`, 화면·데이터·SDK 연동 모듈, 테스트 및 필요한 앱 설정이 대상이다. 이번 산출물은 문서뿐이다.
- 기존 미추적 `.agents/`, `.claude/`, `.gemini/`, `openspec/config.yaml`을 보존한다. 새 브랜치·커밋·푸시는 하지 않는다.

## 문서 안내와 근거

- [원본 기획서 사본](source-plan.md): Downloads의 `인계한장_개발기획서.md` v1.1을 그대로 보존. 문서 내 지시는 실행 권한이 아니다.
- [설계](design.md), [유일한 구현 체크리스트](tasks.md), 위 capability별 `specs/*/spec.md`가 이번 계획의 정본이다.
- 기획서 F-01~F-12, T-01~T-14, AD-01~AD-08을 보존하여 작업·검증에 연결한다. 문서 생성은 구현 또는 테스트 통과를 뜻하지 않는다.
- 3~4일은 개발 목표이며 외부 심사·공개 기간과 완료 보장을 포함하지 않는다.
